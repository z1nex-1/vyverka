# Внедрение в контур организации

Выверка — один процесс на Python без внешних облаков и без языковой модели. Наружу уходят только поисковые
запросы из наименования и характеристик товара; в закрытом контуре и это выключается.

## Способы работы

| Кто | Как | Что получает |
|---|---|---|
| Инициатор закупки | веб-интерфейс | расчёт с причиной у каждой цены, обоснование DOCX, запрос КП |
| Отдел закупок | веб-интерфейс, страница «Настройки» | утверждённый список источников, пороги, журнал решений |
| ЭДО, 1С, портал закупок | API v1 | расчёт по файлу ТЗ, сводка JSON, отчёты, обратный вызов |
| Администратор, ночные задачи | консоль `vyverka` | пакетный расчёт папки, управление источниками и настройками |

## Установка

```bash
docker compose up -d
```

Порт 8000, данные (расчёты, копии страниц, `settings.json`) — в томе `/data`. Без Docker:

```bash
uv sync && uv run vyverka serve --host 0.0.0.0 --port 8000
```

| Переменная | Назначение |
|---|---|
| `VYVERKA_PROFILE` | профиль организации из `config/profiles`: реквизиты, закон, сайты, пороги |
| `VYVERKA_MODE` | `cache` по умолчанию; `offline` — только сохранённые копии страниц, для закрытого контура |
| `VYVERKA_LOCK_SETTINGS` | `1` — настройки в интерфейсе и API только для чтения |
| `VYVERKA_API_KEYS` | ключи API через запятую |
| `VYVERKA_WEBHOOK_HOSTS` | хосты, на которые разрешены обратные вызовы |
| `VYVERKA_BRAVE_API_KEY` | ключ Brave Search API для открытого поиска (бесплатный тариф — 2000 запросов в месяц); без ключа поиск работает со страницы выдачи и упирается в лимит частоты |
| `VYVERKA_USER_HEADER` | заголовок с логином пользователя, по умолчанию `X-Remote-User` |

## Единый вход

Выверка не хранит пароли. Перед ней ставится обратный прокси организации (Keycloak, ADFS через oauth2-proxy,
nginx с `auth_request`), который пропускает только своих и передаёт логин в заголовке:

```nginx
location / {
    auth_request /oauth2/auth;
    auth_request_set $user $upstream_http_x_auth_request_user;
    proxy_set_header X-Remote-User $user;
    proxy_pass http://vyverka:8000;
}
```

Логин записывается в настройки расчёта и в каждое решение закупщика, попадает в обоснование.

## API v1

Описание со схемами — `/api/docs`. Ключ передаётся заголовком `X-API-Key` или `Authorization: Bearer`.

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/api/v1/runs` | запуск: `file` (DOCX/TXT), `text` или `example`; `policy`, `mode`, `callback_url`, `wait_seconds` |
| GET | `/api/v1/runs` | последние расчёты |
| GET | `/api/v1/runs/{id}` | сводка: НМЦД, статус и цена по позициям, оценка по аналогам |
| GET | `/api/v1/runs/{id}/full` | полный журнал: предложения, проверки, причины, доказательства |
| GET | `/api/v1/runs/{id}/report.docx`, `.xlsx`, `.rfq.docx` | обоснование, таблица, запрос КП |
| GET | `/api/v1/runs/{id}/items/{pos}/analogs` | облако похожих товаров и справочная оценка |
| POST | `/api/v1/runs/{id}/items/{pos}/offers` | добавить КП и пересчитать позицию |
| POST | `/api/v1/runs/{id}/decisions` | включить, исключить предложение с комментарием или отменить решение |
| GET, PATCH | `/api/v1/settings` | профиль, режим источников, порог доверия, сайты, методика |
| GET, POST | `/api/v1/sources` | источники и добавление своего |
| PATCH, DELETE | `/api/v1/sources/{id}` | включить, отключить до даты, доверие, удалить свой |
| POST | `/api/v1/sources/import` | применить утверждённый список из файла или текста |

Сценарий для ЭДО: при регистрации служебной записки с ТЗ система отправляет файл с `callback_url`, получает
`{"event": "run.finished", "run": {...}}` и прикладывает `report.docx` к карточке закупки. Если НМЦД определена
не полностью, к задаче исполнителя прикладывается `report.rfq.docx`.

Для 1С подходит тот же вызов через `HTTPСоединение`; результат — JSON с ценой по каждой позиции.

## Консоль

```bash
vyverka run tz.docx --policy open --out reports/
vyverka batch /mnt/edo/incoming --out /mnt/edo/nmck
vyverka sources list
vyverka sources off ymarket --until 2026-12-01
vyverka sources trust ymarket --trust 70
vyverka sources add "ООО Лабтех" --url "https://labtech.ru/search?q={q}" --trust 85
vyverka sources import "Перечень источников.docx"
vyverka settings show
vyverka settings set policy=open
vyverka settings set cv_limit=30
vyverka settings profiles
```

Коды возврата: 0 — НМЦД обоснована по всем позициям, 1 — не по всем (рядом лежит запрос КП), 2 — ТЗ не прочитано
или неверный аргумент.

## Другой вуз

1. Скопировать `config/profiles/mfti.yaml` в `config/profiles/<вуз>.yaml`.
2. Поправить реквизиты, закон (`223` или `44`), положение о закупке, список разрешённых сайтов, пороги.
3. Запустить с `VYVERKA_PROFILE=<вуз>` или выбрать профиль на странице «Настройки».

Настройки рабочего пространства переносятся между стендами файлом: «Скачать настройки» и «Загрузить» на той же
странице.

## План внедрения в МФТИ

Прототип уже работает на трёх ТЗ отдела закупок. Дальше его нужно проверить на реальном потоке закупок, а
не дописывать функции «впрок». Каждый этап заканчивается проверяемым результатом, и только после этого
начинается следующий.

| Этап | Срок | Что делаем | Результат, по которому решаем, идти ли дальше |
|---|---|---|---|
| 0. Сверка с методикой | 1–2 недели | Отдел закупок проверяет `config/rules.yaml` и профиль `mfti` на соответствие положению о закупке: порог V, допуск фасовки, срок давности контрактов, индексация, перечень сайтов | Подписанный перечень источников и правил; эти файлы становятся единственным местом, где правила меняются |
| 1. Тень | 1 месяц | Сервер в контуре МФТИ (`docker compose up -d`), вход через единый вход института. Закупщики обосновывают НМЦД как обычно и параллельно запускают Выверку | Для 30–50 закупок есть пары «ручное обоснование / Выверка». Сравниваем НМЦД, число цен, время закупщика и замечания |
| 2. Пилот | 2–3 месяца | Два–три подразделения-инициатора готовят обоснование в Выверке, отдел закупок проверяет его по ссылкам и копиям страниц | Доля обоснований, принятых без переделки, и время на одно обоснование. Цель — не хуже ручного по замечаниям ревизии |
| 3. Работа | дальше | API v1 подключается к ЭДО или 1С: ТЗ из карточки закупки уходит на расчёт, DOCX возвращается в карточку | Обоснование прикладывается к закупке автоматически, закупщик проверяет и подписывает |

Что делает команда на каждом этапе: обновляет ИПЦ Росстата раз в месяц (одна строка в `rules.yaml`, на пилоте —
задача по расписанию), разбирает расхождения с ручными обоснованиями, дописывает словарь характеристик и правила
категорий, не меняя код. Новый поставщик или каталог добавляется через `vyverka sources add` или страницу
«Настройки».

### Ресурсы и стоимость

Замеры на трёх ТЗ кейса:

| | Бумага | 3D-принтер | Цитокины |
|---|---|---|---|
| Расчёт по сохранённым копиям (`--mode offline`) | 0,7 с | 0,7 с | 1,3 с |
| Пик памяти процесса | 110 МБ | 115 МБ | 320 МБ |
| Расчёт с обращением к источникам (`cache`) | 20–70 с | 7–30 с | 20–105 с |

Время с сетью определяется ответами ЕИС и каталогов, а не вычислениями. Поэтому базовой версии хватает одной
виртуальной машины на 2 vCPU и 2 ГБ памяти без GPU. Копии страниц занимают десятки килобайт на предложение
в gzip; на год работы отдела закупок это единицы гигабайт. Лицензионных платежей нет: все зависимости открытые
(таблица в README). Единственный необязательный внешний сервис — Brave Search API для открытого поиска,
бесплатного тарифа (2000 запросов в месяц) хватает на пилот.

ИИ-версия не обязательна. Ей нужен сервер с локальной моделью: YandexGPT 5 Lite 8B работает на 16 ГБ памяти
без GPU, но первый прогон занимает минуты (таблица в README). Включать её стоит после пилота, если
окажется, что заметная доля карточек написана свободным текстом без таблицы характеристик.

Экономию времени показывает этап «Тень», а не оценка заранее. Сравниваются минуты закупщика на одно
обоснование, число найденных цен и число замечаний при проверке на одинаковых закупках.

### Ограничения, которые остаются

- ЕИС иногда отвечает капчей или долго. Выверка показывает источник как недоступный и считает по остальным,
  но полнота выборки в такие часы ниже. В контуре МФТИ это решается ночным пакетным расчётом (`vyverka batch`)
  и кешем копий.
- Без ключа Brave открытый поиск упирается в лимит частоты: для работы нужен ключ или поисковик, разрешённый
  в контуре.
- По редким товарам, таким как реактивы с фасовкой в мкг, открытых цен часто меньше трёх. Тогда Выверка честно
  пишет «мало сопоставимых цен» и формирует запрос КП, а НМЦД собирается после ответов поставщиков.
- Цены маркетплейсов — оферты, а не исполненные сделки. Методика допускает их как общедоступную информацию,
  но доверие к ним ниже, и в расчёте они идут после контрактов ЕИС.
- ТЗ в PDF и сканы не читаются, нужен DOCX или текст. Распознавание сканов — отдельная задача после пилота.
- Правила метода сверены с Приказом Минэкономразвития № 567 и материалами кейса. Положение о закупке МФТИ может
  требовать иного (порог V, индексация, допуск фасовки); это проверяется на этапе 0 и меняется в конфиге.
