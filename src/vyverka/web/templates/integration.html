Внедрение

Выверка ставится в контур организации и работает без внешних облаков: наружу уходят только поисковые запросы с названием и характеристиками товара. Подключиться можно четырьмя способами — от кнопки в браузере до ночной выгрузки из ЭДО.

1. Веб-интерфейс

Закупщик загружает ТЗ, видит каждую цену с причиной, принимает однородные товары с комментарием, скачивает обоснование DOCX, таблицу XLSX и запрос КП. Настройки источников — на отдельной странице.

Вход — через единый вход организации: обратный прокси (Keycloak, ADFS, oauth2-proxy) передаёт логин в заголовке X-Remote-User, имя попадает в журнал решений и в отчёт.

Выверку можно установить как приложение прямо из браузера: своё окно и значок в панели задач, без адресной строки. Следующий шаг — настольная сборка под Windows, Astra Linux и РЕД ОС поверх того же сервера; сравнение вариантов — в docs/app.md и в справке.

2. API для ЭДО, 1С и портала закупок

Полное описание с примерами — {{ base }}/api/docs. Ключи задаются переменной VYVERKA_API_KEYS.

# запустить расчёт и дождаться результата
curl -s -H "X-API-Key: $KEY" -F file=@tz.docx -F policy=strict -F wait_seconds=90 \
     {{ base }}/api/v1/runs

# или сразу вернуть id, а сводку прислать обратным вызовом
curl -s -H "X-API-Key: $KEY" -F file=@tz.docx -F callback_url=https://edo.local/hooks/nmck \
     {{ base }}/api/v1/runs

# обоснование, таблица, запрос КП
curl -s -H "X-API-Key: $KEY" -o nmck.docx {{ base }}/api/v1/runs/RUN_ID/report.docx
curl -s -H "X-API-Key: $KEY" -o kp.docx   {{ base }}/api/v1/runs/RUN_ID/report.rfq.docx

# пришло КП — добавить и пересчитать
curl -s -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
     -d '{"supplier":"ООО Лабтех","price":18900,"doc":"КП № 41"}' \
     {{ base }}/api/v1/runs/RUN_ID/items/1/offers

# временно отключить источник
curl -s -X PATCH -H "X-API-Key: $KEY" -H "Content-Type: application/json" \
     -d '{"until":"2026-12-01"}' {{ base }}/api/v1/sources/ymarket

Обратный вызов уходит только на хосты из VYVERKA_WEBHOOK_HOSTS — сервис нельзя заставить обращаться во внутреннюю сеть.

3. Консоль и пакетная обработка

vyverka run tz.docx --policy open --out reports/
vyverka batch /mnt/edo/incoming --out /mnt/edo/nmck     # все ТЗ из папки, по cron
vyverka sources list
vyverka sources off ymarket --until 2026-12-01
vyverka sources add "ООО Лабтех" --url "https://labtech.ru/search?q={q}" --trust 85
vyverka sources import "Перечень источников.docx"
vyverka settings set policy=open
vyverka settings set trust_min=70
vyverka settings profiles

Код возврата 0 — НМЦД обоснована полностью, 1 — не по всем позициям (рядом лежит запрос КП), 2 — ТЗ не прочитано.

4. Свой сервер

docker compose up -d                 # порт 8000, данные в томе /data
VYVERKA_PROFILE=vuz44                # профиль организации: mfti, vuz44, research
VYVERKA_MODE=offline                 # закрытый контур: только сохранённые копии страниц
VYVERKA_LOCK_SETTINGS=1              # настройки меняет только администратор
VYVERKA_API_KEYS=ключ1,ключ2
VYVERKA_WEBHOOK_HOSTS=edo.local

Другой вуз подключается файлом config/profiles/<вуз>.yaml: реквизиты, закон, разрешённые сайты, пороги методики. Настройки переносятся между стендами файлом — кнопка «Скачать настройки».
